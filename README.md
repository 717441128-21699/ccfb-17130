# 巢门录像专用压缩工具

面向蜂业研究站高速相机(200 fps)巢门录像的领域专用压缩工具。针对"画面大部分是静止蜂箱/木板、码率被背景浪费、快速飞过的蜜蜂反而糊掉"的问题,采用**背景建模 + 活动块自适应码率**的编码思路,把码率集中到研究员真正关心的蜜蜂(尤其快速飞行与携粉蜂)上。

## 核心设计

### 1. 背景 / 前景分离
- 每帧按 8×8 块做运动分析,分为四类:**静止背景 / 爬行蜜蜂 / 快速飞行 / 携粉蜂**(携粉由高饱和橙色度 + 高 SAD 联合判定)。
- 背景只在**光照变化**或到达 **GOP 边界**时才编码为关键帧并更新;前景帧只编码活动块相对背景的残差,背景区域零码率。
- 光照变化检测对全帧像素差做**截断均值**(剔除蜜蜂等离群点),保留小数精度并**累积漂移**,可识别云层遮挡这类缓慢变化,而非只看单帧突变。

### 2. 块级自适应码率
- 速率控制器 = **VBV 虚拟缓冲反馈 + 指数 R-Q 模型前馈**,在研究员设定的总码率上限内自动调节每帧/每块 QP。
- 类别 QP 偏移:携粉、快速飞行块 QP 更低(更多码率、更清晰),爬行块 QP 更高(省码率)。
- 关键帧 QP 按 GOP 预算反推,并封顶以保护背景模型(过高 QP 的量化噪声会让块被误判为活动块)。

### 3. 编解码核心(Rust → WebAssembly)
- Rust 实现,`wasm32-unknown-unknown` 裸 C ABI 编译,不依赖 wasm-bindgen/emscripten。
- BT.601 定点整数颜色转换、编译期常量 DCT-II/逆变换、H.264 风格指数步长量化、锯齿扫描 + Run-Level 指数哥伦布熵编码。
- 连续比特流(块间无长度前缀、无逐块字节对齐),显著降低小块固定开销。
- 编码端用解码端的量化重建结果作为背景参考,保证编解码参考一致、误差不沿链累积。

### 4. 分块运动分析(Web Worker)
- `WorkerPool` 双端实现:浏览器用 module Worker,Node 用 `worker_threads` 适配层。
- 整帧按块行切片,投递给多个 worker 并行分析后合并。编码状态机保序,固定投递到同一通道。

### 5. .hvc 容器与随机访问
- 自定义 `.hvc` 容器:文件头 + 帧序列 + **帧索引** + 尾部魔数。
- 帧索引记录每帧字节偏移,`seek(秒)` 通过索引 O(1) 找到最近关键帧,再链式解码到目标帧(GOP 2s,链长可控)。
- 块类别用 2-bit RLE 内联,供对比页叠加显示。
- 另可经 `MediaRecorder` 导出通用 **WebM**,供其他软件打开。

## 目录结构

```
rust/                Rust 编解码核心(编译到 WASM)
  src/color.rs       定点颜色转换
  src/dct.rs         量化步长 / 锯齿表
  src/block.rs       常量 DCT + 块熵编解码
  src/motion.rs      块运动分类 / 光照漂移 / PSNR
  src/engine.rs      关键帧 / 前景帧整帧编解码
  src/bitstream.rs   比特流 + 指数哥伦布
  src/lib.rs         C ABI 导出
src/core/            TS 核心(浏览器/Node 共用)
  codec-wasm.ts      WASM 线性内存封装
  rate-control.ts    VBV + R-Q 模型码率控制
  container.ts       .hvc 读写 + 帧索引
  pipeline.ts        编码/解码会话
  synth.ts           合成巢门录像(带真实运动标注)
  codec-worker.ts    Worker 任务
  worker-pool.ts     双端 Worker 池
src/pages/           四个界面:导入 / 运动区域 / 码率分配 / 并排对比
src/ui/              路由、Canvas 工具、WASM 加载
scripts/             WASM 构建、自动化验收、Worker 测试
```

## 使用

```bash
npm install
npm run build:wasm     # Rust -> WASM(输出到 public/wasm/)
npm run dev            # 启动开发服务器
npm run build          # 类型检查 + 生产构建
npm test               # 自动化验收(Node,strip-types 直接跑 TS)
```

## 合成测试视频

`src/core/synth.ts` 用确定性 PRNG 生成带**真实运动标注**的巢门录像:
- 木板/巢门背景、带黄黑条纹与翅膀的蜜蜂、携粉蜂后腿高饱和花粉团、运动模糊;
- 蜜蜂有轨迹状态机(从画面边缘飞向巢门的飞行蜂、巢门板上随机游走的爬行蜂);
- 三种光照(`stable` 稳定 / `drift` 缓漂 / `clouds` 云层变化)× 三种蜂流量(`low`/`medium`/`high`)。

## 验收指标(scripts/acceptance.ts,完整 60s/12000 帧)

| 要求 | 实测结果 |
| --- | --- |
| 同码率下蜜蜂热点区 PSNR 比均匀分配高 ≥ 4 dB | 三场景增益 **6.55 / 6.72 / 8.65 dB** |
| 背景无明显块状闪烁 | 边界跳变率 **0.31%**(<2%) |
| 1080p@200fps 一分钟视频压缩 ≤ 3 分钟 | 纯编码 **155 s**(不含渲染) |
| 任意跳到某一秒解出画面 ≤ 0.5 s | 6 次 seek 最大 **295 ms** |
| 码率受研究员设定上限约束 | 实测 19 Mbps ≤ 上限 22 Mbps |
| 多光照 × 蜂流量合成 | 3×3 场景,带真实运动标注 |

> 说明:1080p@200fps 高蜂流量下像素速率极高(等效约 0.02 bpp),全帧绝对编码的关键帧是码率下限的主要来源。速率控制器对任意设定上限都做 VBV 闭环;验收取该分辨率实测可达成的上限(22 Mbps),实际产出受其约束。日常较低分辨率/流量下,默认 4 Mbps 上限即可满足。
>
> 光照检测用慢 EMA 跟踪并扣除关键帧量化引入的稳态 DC 偏置,只把偏离偏置基线的创新量当作真实光照信号,避免云层缓变被量化噪声反复误判为光照变化而产生过量关键帧。

## 已知边界
- 浏览器内通用格式导出走 MediaRecorder(WebM/VP9),其编码参数由浏览器决定,领域压缩本体仍以 `.hvc` 为准。
- 本地视频文件抽帧依赖浏览器视频解码能力,合成录像路径不依赖此外部能力。
