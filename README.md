# 巢门录像内容自适应压缩工具

面向蜂业研究站高速相机(200 fps、单路一天数 TB)的专用视频压缩工作台。核心思路:
**把画面拆成静止背景与运动区域,背景在 P 帧零字节跳过、仅在光照变化时更新,
码率按蜜蜂运动速度与花粉检测结果倾斜给蜜蜂所在宏块**,从而在固定总码率下
显著提升蜜蜂区域的清晰度,同时避免静态背景的块状闪烁。

## 技术栈

| 层 | 实现 | 说明 |
| -- | ---- | ---- |
| 编解码核心 | Rust(无外部 crate)→ `wasm32-unknown-unknown` | 纯 C ABI,手工实例化,产物 ~60 KB |
| 运动分析 | Rust/WASM 原生 + 等价 TS 回退 | 运行在 Web Worker,不阻塞 UI |
| 前端 | TypeScript + Vite,无框架 | 四个标签页的单页应用 |
| 测试 | Rust `cargo test` + Node `node:test` + 基准脚本 | 覆盖单元、端到端、率失真、性能 |

## 目录结构

```
crates/hive-codec/      Rust 编解码 + 运动分析核心(编译为 WASM)
  src/
    dct.rs              正交 8x8 DCT(14 位定点查表)
    quant.rs            32 档 QP 量化表(x264 风格指数缩放)
    huff.rs             限长 Huffman(Kraft 投影)+ 游程熵编码
    color.rs            BT.601 YUV420 转换
    block.rs            宏块四分类与差异化 QP
    analyzer.rs         背景建模 + 分块运动分析(WASM 原生)
    encoder.rs          I/P 帧、背景跳过、帧内刷新、滑窗码率控制
    decoder.rs          trailer 索引随机访问、逐 MB QP 重建
    container.rs        .hvc 容器(文件头/帧头/I 帧索引 trailer)
src/
  core/                 TS 领域逻辑(合成、运动、码率、指标、导出)
  workers/              运动分析 Web Worker
  wasm/codec.ts         WASM ABI 的 TS 封装
  pages/                四个页面:导入/运动区域/码率分配/并排对比
tests/                  Node 冒烟测试与基准
public/wasm/            构建产物 hive_codec.wasm
```

## 快速开始

```bash
npm install
npm run build:wasm     # Rust → WASM,输出到 public/wasm/
npm run dev            # 启动开发服务器(自动先构建 wasm)
npm run build          # 类型检查 + 生产构建到 dist/
npm test               # Node 冒烟测试(编解码往返、分析器一致性)
npm run bench          # 率失真基准(PSNR 增益、背景闪烁、seek)
npm run bench:perf     # 1080p 吞吐与 seek 延迟
```

Rust 侧单独测试:

```bash
cd crates/hive-codec
cargo test             # 28 个单元/集成测试
```

## 四个页面

1. **录像导入** — 按光照(明亮/阴天/黄昏)× 蜂流量(稀疏/正常/密集)合成带
   逐帧像素级标注的巢门录像,也支持导入本地视频抽帧。
2. **运动区域** — Web Worker 逐帧分块分析,叠加显示背景/爬行/飞行/花粉四类
   宏块,给出分类统计与平均亮度曲线。
3. **码率分配** — 设定总码率上限或固定 QP,WASM 编码并展示逐帧字节、达到码率
   与压缩比,可下载 `.hvc`。
4. **并排对比** — 任意秒级随机 seek,原始/解码帧并排,分区域 PSNR,并可导出
   WebM / MJPEG 通用格式。

## 关键设计决策

- **背景跳过 + 重新暴露刷新**:P 帧背景 MB 仅在与参考帧 SAD 一致时跳过;
  蜜蜂飞离后重新露出的背景会被强制帧内刷新,避免错误继承残留像素。
- **逐 MB QP 写入容器**:每帧保存类别图,解码端按 MB 重算有效 QP,保证
  反量化表与编码端严格一致(这是码率再分配能正确还原的前提)。
- **运动 MB 帧内刷新**:大幅运动的残差信号动态范围大,对飞行/花粉 MB 采用
  帧内预测(pred=0),比纯帧间残差的 PSNR 高约 5 dB。
- **随机访问**:容器尾部保存 I 帧偏移索引,二分定位后从最近 I 帧顺序重建,
  无需从头解码。

## 指标实测结果(320×240 @200fps,见 `npm run bench`)

| 场景 | 蜜蜂区 PSNR 增益(同码率 vs 均匀分配) | 背景闪烁 | 最大 seek |
| ---- | ---- | ---- | ---- |
| 黄昏/稀疏 | **+4.97 dB** | 0.000 | ~64 ms |
| 明亮/正常 | +2.08 dB | 0.000 | ~113 ms |
| 阴天/密集 | +1.38 dB | 0.000 | ~202 ms |
| 背景 PSNR | 33–36 dB(无可见块状闪烁) | | |

- 稀疏场景(背景占比 ~95%)严格满足需求的 **≥4 dB**;蜜蜂占比升高后可再分配
  的背景字节减少,增益相应收窄,属率失真的物理特性。
- seek 全部远优于 500 ms 门槛。

## 已知性能边界

1080p/200fps 单线程 WASM 实测约 100 ms/帧(外推一分钟录像约 20 分钟),
未达到"3 分钟压缩一分钟"的目标。瓶颈在 200 万像素/帧的逐像素亮度计算与
背景建模的内存带宽,而非算法复杂度。生产环境的达标路径:

- 启用 **WASM SIMD**(亮度/色彩/SAD 向量化,预期 2–3×);
- **多 Worker 按行分片并行**(分析器无共享状态,近线性扩展到 4–8 核)。

两者均不需要改变现有容器格式与编解码算法。`npm run bench:perf` 会如实报告
当前吞吐与所需提速倍数。
